# 08 — Art pipeline

## Style

Low-poly, flat-shaded, few colours, strong silhouettes. No textures in the first
milestones: vertex colours or one flat material per part. Ships read at a glance from
50 m away. Hazard colour code is fixed:

| hazard | colour |
|---|---|
| fuel | orange |
| coolant | cyan |
| power | yellow |
| pressure | white stripes on grey |

Lighting: one sun (DirectionalLight3D), hard shadows, a dim blue fill from the planet.
Space is very dark; the ship's work lights matter.

## Blender, headless, scripted

Parts are generated by Python scripts run headless with Blender 5.2 LTS:

```
blender -b -P tools/blender/<script>.py -- --out godot/assets/models/parts --name <part>
```

`tools/blender/make_part.py` is the template. Scripts are the source of truth; the
committed `.glb` is output. To change a part, change the script and re-run it.

## Conventions (enforced by `godot/tests/test_part_import.gd`)

- 1 Blender unit = 1 metre.
- Part forward is Blender +Y. It becomes Godot -Z on import.
- The mesh object is named exactly the part name (`hull_segment_a`). Godot wraps it
  in a root node and appends a suffix to the root name; code should find the
  `MeshInstance3D` by type, not by root name.
- `SOCKET_<name>[_<size>]`: attachment empties. `+Y` of the empty points out of the
  part. Size is `S`, `M`, or `L`; omitted means `M`. Two sockets connect only if
  sizes match.
- `CUT_<name>`: cut points, usually one per socket, 0.4 m inboard.
- `HAZARD_<kind>_<n>`: kind is `fuel`, `coolant`, `power`, or `pressure`.
- Custom properties on the mesh object: `part_kind`, `mass_kg`, `value_cr`,
  `material`, `volume_m3`, `thickness_mm`. Godot exposes them as
  `mesh.get_meta("extras")`, a Dictionary.
- Collision: name the mesh object with the `-convcol` suffix when convex collision
  should be generated on import (Godot strips the suffix). M2 adopts this in both
  scripts and verifies a convex shape on every part. The catalog extracts shapes
  into the dynamic compound body; imported static preview bodies are not nested
  inside that dynamic body.

M2 kit: `make_part_kit.py` generates `hull_segment_a/b`, `cap_nose_a`, `cap_tail_a`,
`tank_fuel_a`, `tank_coolant_a`, `engine_chemical_a`, `engine_ion_a`,
`radiator_panel_a/b`, `sensor_mast_a`, and `plating_panel_a`. Run it with
`--out godot/assets/models/parts`, then run `./check.sh`. The original hull retains
its geometry, mass, and markers. New cut markers sit on the outer surface near
their sockets for accessible aiming. Socket size suffixes are stripped when
matching them to unsized CUT marker names. `volume_m3` is an envelope estimate
for handling/cargo, while `thickness_mm` sets cutter duration; neither is a
material-volume-derived mass calculation. All meshes stay below 2,000 triangles.

## Import

Default Godot glTF import settings. Commit the `.import` sidecar files. Run
`./check.sh` after adding a model so the import happens and the test sees it.

## What GPT should do with Blender

Generate the kit in scripts. Prefer parametric functions (`hull_segment(length,
radius, taper)`, `tank(radius, length)`, `radiator(width, height, fins)`) over unique
hand-built meshes, so the generator can request variants. Keep each part under
2,000 triangles. Check every new part with the import test and by viewing it in the
editor.
